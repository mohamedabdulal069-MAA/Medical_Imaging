## Prepare one split and reuse it across baselines

The archives contain no DICOM dataset or labels CSV. Supply the RSNA long-form `ID,Label` CSV and its corresponding DICOM folder:

```powershell
.\.venv\Scripts\python.exe -m ich.cli prepare --labels 'D:/dataset/stage_2_train.csv' --dicoms 'D:/dataset/stage_2_train' --output data/manifest.csv --seed 42
```

Preparation pivots complete labels before splitting. It requires real PatientID, StudyInstanceUID, SeriesInstanceUID and SOPInstanceUID metadata; never substitute image filenames for patient identity. Confirm deidentified patient identifiers remain stable across all studies and source datasets before using the split. For multi-site data, establish a reviewed patient identity mapping before ingestion.

The default allocation is approximately 70/15/15 percent of patients, with all images for a patient assigned together. It is deterministic and independent of input row order. It is not multilabel stratified; inspect the resulting per-label support before committing to a study protocol. Missing labels, conflicting duplicate labels, duplicate image/SOP IDs, missing metadata, and cross-patient exact HU-image copies fail preparation. Unsupported/corrupt DICOMs fail visibly. Exclusions must be reviewed and recorded outside this tool; no images are silently dropped.

The manifest is local research data and includes source patient IDs and file paths. It should stay with the restricted dataset. Keep the same manifest for every model comparison. Do not repeatedly redraw a split based on test label support or results.

### Resumable scan and observed RSNA unreadable file

Kaggle inspection reproduced a decoding failure for `ID_6431af929.dcm`: 512×512×1 pixels at 16 bits require 524288 bytes, but its uncompressed Explicit VR Little Endian PixelData contains 153710 bytes. The full file is 154410 bytes. The cause (truncation versus incorrect metadata) is not inferred or repaired. This image may be excluded explicitly with the new `ich.manifest_scan.prepare_resumable(..., exclude_confirmed_short_payload=True)` API. That exception requires the exact observed identity, metadata/size signature, and decoder failure. A readable replacement is retained; other unreadable images prevent final manifest creation.

`kaggle-resume-manifest.txt` is a complete paste-ready Kaggle cell, generated by `audit/make_kaggle_resume_cell.py`. It works with the original uploaded package and requires no new dataset upload. It records exclusion evidence/checksum and excluded labels, retains warnings in audit files, prints progress every 1000 images, and commits a SQLite checkpoint every 100 images. Graceful interruption commits completed rows; abrupt termination can require re-reading the last uncommitted batch. Re-running the same cell resumes while the checkpoint files remain available. The earlier non-checkpointed scan cannot be recovered.

The checkpoint is intended for an immutable dataset mount. It binds the source location, labels checksum, preprocessing code, scanner version and decoder/NumPy versions. Per-file size/mtime changes trigger re-reading; these checks are not a proof that a mutable source is unchanged. Use a new checkpoint directory for changed dataset versions. All original patient/image/study/series/copy checks are applied before writing the final split. Preserve `/kaggle/working/rsna-manifest-checkpoint/` with your research outputs; it is not automatically durable across discarded Kaggle sessions. The existing `prepare` CLI remains strict and non-resumable.

## Train, evaluate, and infer

### Resolving identical images with inconsistent annotations

The Kaggle scan reported 4073 cross-patient exact-HU-image groups (8146 images, 251 patient IDs); 838 pairs had at least one conflicting label. These are user-reported dataset QC counts, not experimental performance. No label is adjudicated from those counts.

`kaggle-finalize-cohort.txt` is a paste-ready cell that updates the working code, runs leakage/cohort tests, and finalizes the completed scan without rereading DICOMs. It explicitly selects this conservative cohort policy:

1. Build connected components of patient IDs linked by exact HU hashes, including transitive links, before any image exclusions. Preserve original patient IDs; a shared split group does not assert a verified shared identity.
2. Quarantine every copy of an image whose labels disagree. Do not choose a label by majority vote or combine labels.
3. For each remaining repeated HU image, retain the lexicographically first image ID and record all redundant copies and the retained representative. This applies to same-patient copies too, and avoids counting identical images repeatedly in evaluation.
4. Assign complete linked groups to partitions. Keep all patient, study, series, SOP, image and hash disjointness checks and add a split-group check. Study/series ownership conflicts still fail.

The new manifest is `/kaggle/working/rsna-reviewed-cohort-v1/manifest.csv`; use THAT path for training and evaluation. The folder records exclusions with original labels, unreadable-image evidence, the full patient-group map, split counts, positive-label counts and the exact policy. It protects an existing output folder from overwrite. Source images, labels and checkpoint records are retained unchanged. The API defaults to refusing label conflicts unless `quarantine_conflicts=True` is explicitly selected.

This changes the evaluable cohort and can introduce selection bias; record exclusion counts and class distributions in any research report. The policy resolves data ambiguity conservatively, not clinically. Review questionable image/identity/label provenance separately before claiming generalization to the excluded population. Fixed seed/fractions are unchanged, but allocation is now by linked group rather than individual recorded PatientID. Retain the patched code with this manifest; group assignments participate in its reproducibility digest.

```powershell
$env:PYTHONHASHSEED='42'
.\.venv\Scripts\python.exe -m ich.cli train --manifest data/manifest.csv --baseline resnet50 --output runs/resnet50-s42 --epochs 3 --seed 42
.\.venv\Scripts\python.exe -m ich.cli evaluate --manifest data/manifest.csv --bundle runs/resnet50-s42 --output runs/resnet50-test --partition test
.\.venv\Scripts\python.exe -m ich.cli predict --bundle runs/resnet50-s42 --dicom 'D:/dataset/example.dcm'
```

Baseline choices: `vgg16`, `resnet50`, `densenet121`, `efficientnetb0`, `inceptionv3`, `ensemble` (EfficientNetB0 + ResNet50), and `pca_ensemble` (ResNet50 + EfficientNetB0 + InceptionV3 features → PCA → original dense head).

```powershell
.\.venv\Scripts\python.exe -m ich.cli train --manifest data/manifest.csv --baseline pca_ensemble --components 512 --epochs 5 --output runs/pca-s42
```

ImageNet initialization downloads official Keras weights on first use. All backbones remain frozen as in the originals. Input images are streamed in batches. PCA training materializes frozen feature matrices for train and validation only, so budget memory for N × 5376 features. `--components` must not exceed training sample count or feature count. The default loss is ordinary binary cross entropy; `--weighted-loss` enables six positive-label weights computed only from training data. Its use is an explicit protocol choice, not an inferred correction to historical results.

Only validation loss selects the saved epoch. Test data is never used by the optimizer, PCA fitting, or checkpoint selection. File identities/hashes are verified before training/evaluation; this reads test image content for integrity checks, not learning. Fixed thresholds are 0.5 for every label; no automatic threshold search or test calibration occurs. Keep test evaluation until model/protocol choices are frozen. Repeated evaluation is technically possible, so study governance must prevent test-driven selection.

Each successful run contains `model.keras`, `metadata.json`, `history.json`, and the exact split manifest. PCA runs also contain `extractor.keras` and `pca.npz`. Completion metadata is written only after finite training and saved weights. New run/evaluation directories are required, protecting prior artifacts. Failed run directories have no valid completion marker. Bundles carry artifact hashes, source hashes, seeds, versions, devices, size, label order, preprocessing windows, and PCA fit IDs. Load only bundles you trust; checksums detect accidental changes, not malicious replacement of an entire bundle.

Evaluation writes probabilities and targets keyed by image ID, per-label confusion counts, sensitivity/specificity, precision/F1, ROC AUC, average precision, micro F1, exact match, binary accuracy, BCE, and weighted log loss. Undefined rates/AUC are JSON `null`; macro summaries explicitly average defined labels. These are **slice-level** estimates. They do not establish patient-level performance or patient-cluster confidence intervals. The independent `any` output is retained; hierarchy violations are counted rather than silently rewriting predictions.

## Modules

| Module | Responsibility |
|---|---|
| `dataset` | Label validation, metadata manifest, exact-copy checks, patient splits, file verification, streaming |
| `preprocessing` | Signed CT pixels → HU → fixed windows → float32 [0,255] channels |
| `models` | Five CNNs, two ensembles, serialized model-specific ImageNet adapters |
| `transforms` | Training-ID-guarded PCA; portable NPZ state with no pickle loading |
| `losses` | Binary loss and optional training-only positive weights |
| `metrics` | Explicit multilabel metric definitions and undefined cases |
| `training` | Seeding, validation selection, post-training saves, run provenance |
| `resumable` | Bounded CNN training, model/optimizer/batch recovery, integrity checks during loading |
| `evaluation` | Bundle verification, shared inference, held-out prediction reports |
| `explainability` | Explicit class-specific Grad-CAM for trained image models |

Label order is epidural, intraparenchymal, intraventricular, subarachnoid, subdural, any. Grad-CAM is a model attribution, not a segmentation or diagnosis. ## Resumable Kaggle CNN training

`kaggle-start-resumable-training.txt` is a complete installation, synthetic-test and
first-segment cell for the restored reviewed cohort. It starts a NEW ImageNet
ResNet50 experiment (seed 42, frozen backbone, unweighted binary crossentropy,
Adam 1e-4, batch 16, three fixed epochs). It does not reuse pilot weights or select
settings from test results. Its first invocation is limited to 100 batches or
approximately 45 minutes, whichever comes first. Limits are checked between
batches; metadata checks, downloads, checkpoint writes and a slow batch can extend
elapsed time. No performance or throughput is guaranteed.

Run `kaggle-continue-training.txt` to continue the SAME experiment in further
45-minute segments. Do not run concurrent writers, change accelerator/environment,
or rerun original preparation cells. `kaggle-backup-training.txt` packages the run,
reviewed cohort and exact patched code after a segment returns. Download this
archive before ending a session; `/kaggle/working` alone is not durable storage.
Restore these folders from that new archive before continuing in a new session.
The older preparation backup contains no full-run optimizer or weights.

The runner checks patient/group/duplicate partition integrity from the manifest.
For every train/validation image actually consumed it decodes once, checks DICOM
identity and HU hash against that manifest, then windows those same HU pixels.
It avoids a separate full DICOM prescan and holds only one batch in memory,
with up to four concurrent CPU readers. Each epoch still loads its images;
there is no unverified persistent pixel cache. Test pixels are never opened.
This makes no claim that near-duplicate images or incorrect source identities
have been fully ruled out. UID syntax warnings alone are filtered in the starter
cell; the prior scan warning reports remain available.

Model, optimizer, progress and loss accumulators are published as one checkpoint
generation using an atomic pointer update; the prior generation is retained.
Unexpected interruption replays only batches after the last committed checkpoint.
Training and validation positions are resumable. Source/dependency versions,
partition digest, seed, model, batch size and epoch count are checked on resume.
The resumed data order and optimizer position are preserved, but dropout RNG
continuity across processes is NOT guaranteed bit-for-bit. Record interruptions
when reporting experiments. Final bundle metadata is written only after all
three epochs and validation passes finish; no test score is calculated here.

This runner uses ONE GPU and supports the five CNNs plus the feature ensemble.
The PCA ensemble remains preserved in `training.py` with its training-only fit
guard; it is explicitly rejected by the new runner pending a separate resumable
feature/PCA workflow. The original evaluation API still verifies all manifest
files up front; do not invoke it casually for a full cohort. Pilot outputs and
synthetic regression tests are not evidence of clinical effectiveness.
